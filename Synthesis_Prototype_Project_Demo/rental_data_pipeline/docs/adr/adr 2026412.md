## Problem Statement
Build a reliable analytics pipeline for equipment rental operations so leadership can move from descriptive reporting to prescriptive decision making.

## Business Goals
- Build a trusted rental master dataset for decision support.
- Reduce manual consolidation effort across 25 vendors.
- Enable analytics for rent-vs-buy decisions.
- Track compliance for weekly and monthly vendor updates.

## Analytics Users
- Administrator
- Super User (operations approver)
- Vendor (restricted to own company data)
- Executive consumers in Power BI

## Data Sources
- Vendor uploads (CSV/JSON) from approximately 25 vendors (dummy CSV seeded).
- Validation and staging records in Django/SQL tables.
- Compliance signals from vendor audit tracking.

## Core Metrics
- Total on-rent spend by vendor and period.
- Equipment category utilization trend.
- Vendor submission compliance rate.
- Late submission count by cycle.
- Rent-vs-buy candidate opportunities.

## Data Model Requirements
- Staging table: rental_staging for intake and validation.
- Master table: rental_master as single source of truth.
- Audit table: vendor_audit for login, submission, and verification status.
- Required dimensions: vendor, equipment class, time period, location, cost center (if available).

## Data Quality Rules
- Hard validation for date and currency fields.
- Reject malformed records with actionable error output.
- Preserve source metadata for traceability.
- Enforce approved-only promotion from staging to master.

## Known Limits in Current Build
- Validation currently emphasizes date/rate parsing at seed and workflow level, not full rules-engine coverage.
- Compliance status is tracked, but "No Changes this week" submission handling is not fully implemented.

## Reporting Requirements
- Power BI integration deferred until PostgreSQL migration. Plotly embedded in Django (`/analytics/`) is the confirmed reporting layer for this build.
- All analytics read from `rental_master` via Django ORM — no direct DB connector required.
- Publish standard dashboard views for operations and leadership.
- Include compliance and exception pages.
- Include rent-vs-buy recommendation indicators.

## Non-Functional Requirements
- Secure authentication and role-based access.
- Data refresh process supports weekly/monthly vendor cadence.
- Scalable for portfolio in the $2M to $3M annual range.

## Acceptance Criteria
- Approved data can be queried in Power BI without manual reshaping.
- Compliance metrics are available for each vendor cycle.
- Rent-vs-buy indicator can be calculated from stored data.
- Validation failures are visible and reproducible.

## Open Questions
