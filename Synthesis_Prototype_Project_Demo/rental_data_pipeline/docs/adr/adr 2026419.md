## Problem Statement
Advance the equipment rental analytics pipeline from a validated staging/master architecture to a fully operational reporting platform with automated compliance enforcement and Power BI connectivity.

## Business Goals
- Complete the vendor compliance submission loop (including "No Changes this week" path).
- Implement deadline-based automation to flag late vendors and trigger SMTP nudges.
- Maintain embedded, role-scoped portal analytics as the primary reporting surface.
- Lay groundwork for rent-vs-buy indicator calculations.

## Analytics Users
- Administrator
- Super User (operations approver)
- Vendor (restricted to own company data)
- Executive consumers via embedded portal analytics (Plotly/Django tab)
- Power BI as a future exec-layer export target (deferred pending DB migration)

## Data Sources
- Vendor submissions and compliance signals from Django staging/audit tables.
- `rental_master` as the analytics single source of truth (already populated via publish workflow).
- Market rate reference table (planned) to support rent-vs-buy analysis.

## Core Metrics
- Total on-rent spend by vendor and period.
- Equipment category utilization trend.
- Vendor submission compliance rate (weekly and monthly cycle).
- Late submission count per cycle.
- Rent-vs-buy candidate opportunities by equipment class.

## Data Model Requirements
- Staging table: `rental_staging` — intake and validation (existing).
- Master table: `rental_master` — single source of truth (existing).
- Audit table: `vendor_audit` — login, submission, compliance status (existing).
- New: market rate reference table for rent-vs-buy threshold comparisons.
- Required dimensions: vendor, equipment class, time period, location, cost center.

## Data Quality Rules
- Hard validation for date and currency fields (existing).
- Reject malformed records with actionable error output (existing).
- "No Changes" flag must be a verified action, not a default/null state.
- Deadline timestamps must be stored on audit records for cycle compliance reporting.

## Known Limits Entering This Session
All items resolved. Remaining open items:
- `EquipmentMarketRate` table is seeded with no rows in the current dev environment — `rvb_candidate` will be `False` on all records until rates are entered via admin.
- Power BI integration deferred pending PostgreSQL migration.
- MFA / 2FA deferred to a future session.

## Reporting Requirements
- **Primary (this build):** Embedded Plotly analytics tab at `/analytics/` served by Django, reading from `rental_master` and `vendor_audit` via the ORM.
  - Chart 1: Total on-rent spend by vendor (bar chart).
  - Chart 2: Vendor submission compliance heatmap by cycle.
  - Chart 3: Equipment category utilization trend (line chart).
  - Chart 4: Rent-vs-buy flag table (filterable by equipment class).
- Role scoping: vendors are blocked from `/analytics/`; analytics is restricted to junior super users.
- **Future (Power BI):** Once DB is migrated to PostgreSQL, `rental_master` can be connected via the Power BI PostgreSQL connector for exec-layer dashboards. No SQLite workaround will be implemented.

## Non-Functional Requirements
- Secure authentication and least-privilege role access (existing).
- SMTP credential handling must not appear in committed code.
- Data refresh aligns with weekly (Thursday 2:00 PM CST) and monthly cadences.
- Scalable for $2M–$3M annual rental portfolio.

## Acceptance Criteria
- ✅ Vendor can submit a "No Changes this week" record that is captured and visible in audit log.
- ✅ Deadline automation job identifies unverified vendors and sends SMTP nudge with Super User CC.
- ✅ `/analytics/` tab loads with role-scoped Plotly charts populated from `rental_master` and `vendor_audit`.
- ✅ Vendor user is blocked from `/analytics/` (HTTP 403).
- ✅ Admin user is blocked from `/analytics/`; reviewer analytics access is via junior super user role.
- ✅ Rent-vs-buy indicator field is populated at publish time and shown in the analytics tab.
- ✅ Validation failures remain visible and reproducible.
