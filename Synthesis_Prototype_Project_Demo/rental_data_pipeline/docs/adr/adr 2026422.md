## Problem Statement
Begin Phase 2 of the vendor compliance pipeline by implementing a realistic W17 submission simulation, establishing fake vendor email infrastructure, and validating the end-to-end intake and approval pipeline under mixed submission conditions (new equipment, no-change declarations, and late/non-submission scenarios). Additionally, establish an admin-managed approved equipment category table and enforce referential integrity of equipment categories across all database records.

## Business Goals
- Demonstrate that all eight W17 submission scenarios (S-01 through S-08) can be exercised through the existing UI and management commands without requiring code changes to the core workflow.
- Establish email account infrastructure for all 25 vendor users so that SMTP nudges and submission receipts are routable to realistic addresses.
- Validate that `/review/` stat cards, compliance badges, and the consolidated table accurately reflect a mixed-state vendor week.
- Confirm that `check_deadlines` correctly identifies late and non-submitting vendors when run against a W17 cycle date.
- Confirm that the Week Comparison tab on `/analytics/` correctly surfaces W17 equipment additions and removals relative to W16.

## Analytics Users
- Administrator (read-only access, blocked from `/analytics/`)
- Junior Super User (primary analytics and review consumer)
- Vendor (restricted to own company data; blocked from `/analytics/`)
- `ApprovedEquipmentCategory` — Admin-managed table of approved equipment category names. Replaces the hardcoded Python list previously imported from `seed_market_rates.py`. Drives vendor portal `<select>` dropdown and analytics category filter.
- `rental_staging` — W17 submission rows created by `simulate_vendor_week` command and manual vendor portal entries.
- `vendor_audit` — cycle compliance records for Week 17 across all 25 active vendor companies.
- `rental_master` — W16 baseline data used for Week Comparison delta calculations.
- `EquipmentMarketRate` — reference table used for RvB flag assignment on published rows.
- `PODepartment` — PO→mill department mapping applied to all staged and published rows.

Zero unapproved categories remain in either table. `classify()` function in `backfill_staging_categories.py` updated with the missing keyword patterns so future imports map cleanly.

  - **S-01 (No Change):** 4 vendors declared `no_change=True` with `verified=True` on audit.
  - **S-02 (New Equipment):** 2 vendors submitted new staging rows that passed validation and were queued for publish.
  - **S-03 (Equipment End-Dated):** 2 vendors submitted rows with `on_rent_end` set; "Taken Off Rent" logic confirmed on `/analytics/` Week Comparison tab after publish.

## Data Quality Rules
- Hard validation retained: date format, positive rate, positive quantity.
- Duplicate `(vendor_name, equipment_id)` per week detected and rejected at view layer (S-08).
- `on_rent_start <= on_rent_end` OR `on_rent_end` is null enforced in model `clean()`.
- `publish_to_master` skips rows where `is_validated=False`; all valid W17 rows published successfully.
- Equipment category values in `RentalMaster` and `RentalStaging` now fully constrained to the approved list. Future vendor submissions use a `<select>` populated from `ApprovedEquipmentCategory`, eliminating free-text category entry.
- Equipment category fallback is `"Other"` (in approved list); no row can receive an unapproved category through the portal.
- PO→department assignment applied to all new W17 staging rows via `PODepartment` lookup.

- `simulate_vendor_week` assigns vendors to scenarios deterministically by index; production system would require a UI-driven assignment tool.
- Approval confirmation email (sent after super user publishes) deferred to Phase 2.4.
- Submission timestamps in `simulate_vendor_week` are synthetic (set via `submitted_at` override); not wall-clock accurate for S-06 late-submission testing without manual time manipulation.
