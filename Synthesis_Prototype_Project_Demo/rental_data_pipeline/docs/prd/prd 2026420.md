## Product Vision
Deliver a fully operational equipment rental data platform with a closed vendor compliance loop, automated deadline enforcement, and an embedded Plotly analytics tab with department-centric filtering and period-aware visualizations — enabling operations and leadership to make rent-vs-buy decisions from trusted, timely data served directly from the Django portal.

## Objectives
- Complete analytics refinement: fix ISO week bucketing for monthly/quarterly/yearly views; add searchable filters with datalist autocomplete; implement period-independent chart controls.
- Introduce mill department mapping for POs, replacing vendor-code-based area filtering with domain-specific department entities (Coke, Iron, Steel, Plate, Hot Mill, Cold Mill, MEU).
- Populate equipment category from market rate reference table, enabling category-based filtering and utilization analysis.
- Optimize tab-switching performance with targeted Plotly resize and loading spinner feedback.
- Lay groundwork for Phase 2 vendor email integration and realistic submission scenarios.

## Personas and Permissions
- Administrator: access-control and configuration management in Django admin.
- Junior Super User: weekly review, publish decisions, and analytics consumption via `/review/` and `/analytics/`.
- Vendor: submit equipment updates or declare no changes for the current cycle; restricted to own company data.

## Scope

### In Scope (This Session - 2026-04-20)
- **ISO Week Bucketing Fix:** Corrected calendar year derivation in monthly/quarterly/yearly period grouping. Week 1 of 2026 (starting Dec 29, 2025) now correctly buckets into 2025-12, not 2026-12.
- **PODepartment Model & Mapping:** New Django model linking all 764 distinct POs to one of 7 mill departments. `seed_po_departments` command assigns departments randomly. Admin list allows manual editing.
- **Equipment Category Population:** RentalMaster extended with `equipment_category` field, backfilled via `populate_equipment_category` management command matching descriptions to EquipmentMarketRate entries. 28 categories identified and populated across 1,695 active rows.
- **Searchable Filters with Datalist:** Converted Department, Supplier, Category, and PO filters from `<select>` dropdowns to `<input type="text">` with `<datalist>` autocomplete. Filters remain fully functional with real-time slicer updates.
- **Volume Over Time Period Controls:** Added independent Week/Month/Quarter/Year buttons to Volume chart. Period state decoupled from Cost chart period state.
- **Performance Optimization:** Replaced global window resize event with targeted `Plotly.Plots.resize()` calls. Added CSS spinner overlay on tab transitions for loading feedback.
- **Analytics RVB Table Enhancement:** RVB table rows now include `mill_department` for seamless filtering integration.

## Functional Requirements

### Analytics Filtering & Visualization
- **FR-FILT-01:** Department filter must display all 7 mill departments from PODepartment table.
- **FR-FILT-02:** Supplier filter must display all unique vendor names.
- **FR-FILT-03:** Rental Category filter must display all unique equipment_category values.
- **FR-FILT-04:** PO Number filter must display all distinct PO numbers from dashboard rows.
- **FR-FILT-05:** All four filters must support text search via datalist autocomplete; filtering results update charts in real time.
- **FR-CHART-01:** Cost Over Time chart must correctly rebucket weekly data into monthly, quarterly, and yearly aggregates based on calendar year (not ISO year).
- **FR-CHART-02:** Volume Over Time chart must have independent period controls (Week/Month/Quarter/Year) separate from Cost chart period.
- **FR-CHART-03:** X-axis on both over-time charts must end exactly at the last data point (type: category, range clamping).
- **FR-CHART-04:** Tab transitions must show loading spinner for visual feedback; spinner fades out once chart resize completes.

### PO Department Mapping
- **FR-POD-01:** All 764 active POs must be assigned to one of 7 mill departments.
- **FR-POD-02:** Assignments must be random on first seed; `--reset` flag on `seed_po_departments` allows re-randomization.
- **FR-POD-03:** Admin can manually edit department assignment for any PO via admin list interface.
- **FR-POD-04:** PO→department mapping must be used in place of vendor_code for "By Area" filtering throughout analytics.

### Equipment Category
- **FR-CAT-01:** RentalMaster records must be populated with equipment_category from EquipmentMarketRate based on equipment_description match.
- **FR-CAT-02:** Records with no matching market rate must show "Uncategorized" as fallback.
- **FR-CAT-03:** Rental Category filter must use equipment_category (not equipment_description).
- **FR-CAT-04:** "By Rental Category" chart must aggregate by equipment_category (not full description).

### Performance
- **FR-PERF-01:** Tab switching must not trigger unnecessary Plotly relayouts on hidden charts.
- **FR-PERF-02:** Loading spinner must appear on tab transition, fade out once visible chart is ready.

## User Flows

### Analytics Filtering Flow
1. User navigates to `/analytics/`.
2. User clicks Department filter → datalist shows sorted list of 7 departments.
3. User types "Hot" → datalist filters to "Hot Mill".
4. User selects "Hot Mill" → Cost, Volume, Spend, Category charts all refilter in real time.
5. User can now combine Department + Supplier + Category + PO filters for multi-dimensional analysis.

### Period Bucketing Flow
1. User navigates to Analytics → Cost Over Time tab.
2. User clicks "Month" button → chart x-axis rebuckets from weeks to calendar months, y-axis scales accordingly.
3. Visible periods slider adjusts visible window independently of period granularity.
4. User switches to Volume tab; Volume retains its own independent period state (may still be "Week" while Cost is "Month").

### Tab Transition UX Flow
1. User is on Cost Over Time tab.
2. User clicks "By Department" tab.
3. Loading spinner appears immediately over chart area (opacity fade-in).
4. JavaScript triggers targeted Plotly resize on the visible chart.
5. Chart renders; spinner fades out (opacity fade-out) and is removed from DOM.
