## Product Vision
A fully operational equipment rental data platform with a time-gated vendor submission window, accurate per-vendor cadence tracking, a closed vendor compliance loop, high-performance analytics, and reproducibly documented environment. The platform enforces data integrity at every layer and prevents vendor submission after a week has been published.

## Objectives
- Enforce a vendor submission window that opens Monday at midnight and closes automatically when the reviewer publishes the week, with no extra state management.
- Provide developer testing commands to reset a published week and bulk-pre-fill vendor submissions for repeatable walkthrough testing.
- Restore per-vendor submission cadence (weekly vs. monthly) tracking so audit records accurately reflect each vendor's expected reporting frequency.
- All objectives from prd 2026424.md remain fully implemented and in effect.

## Personas and Permissions
- **Administrator:** Access-control and configuration management in Django admin. Can update `VendorCompany.cadence` for any vendor.
- **Junior Super User (Reviewer):** Weekly review, delinquent vendor resolution, publish decisions, analytics. Publish action triggers window close for that week.
- **Viewer *(concept — not implemented)*:** Read-only `/analytics/` access. Future enhancement.
- **Vendor:** Submit equipment updates or declare no changes during the open window only; restricted to own company data.

## Scope

### In Scope (This Session - 2026-04-30)

#### Submission Window Gate
- **Window Open Condition:** `VendorAudit` records exist for the current ISO week (created by `advance_cycle`); `RentalMaster` has no rows for `cycle_week=current_week, cycle_year=current_year`.
- **Window Closed Condition:** `RentalMaster.objects.filter(cycle_week=w, cycle_year=y).exists()` returns `True` — i.e., the reviewer has published.
- **`vendor_dashboard` View:** Computes `window_closed` boolean and `current_cycle_date`; passes both to template context.
- **`vendor_declare_no_change` View:** Returns redirect with error message if window is closed.
- **`vendor_no_change_ajax` View:** Returns HTTP 400 JSON `{"error": "Submission window is closed"}` if window is closed.
- **`vendor_csv_upload` View:** Returns HTTP 400 JSON error if window is closed.
- **`vendor_dashboard.html` Template:**
  - Submit section has three exclusive branches: `{% if window_closed %}` → locked badge, `{% elif audit and not audit.verified %}` → active submit button, `{% elif audit and audit.verified %}` → completion checkmark.
  - CSV upload panel wrapped in `{% if audit and not audit.verified and not window_closed %}`.

#### Testing Management Commands
- **`reset_week` Command:**
  - Deletes all `RentalMaster` rows for target week (`--week`, `--year`; defaults to current ISO week).
  - Updates all `VendorAudit` rows for that week's `cycle_date` to: `verified=False`, `is_late=False`, `no_change=False`, `no_change_declared_at=None`, `submitted_at=None`, `notes=""`.
  - Outputs count of deleted master rows and reset audit records.
  - Side effect: reopens the submission window automatically (no master rows → window open).
- **`bulk_submit_vendors` Command:**
  - Accepts `--week`, `--year`, `--skip` (default: `vendor_smith_llc`).
  - Resolves skip company name from `UserProfile.company` for the given username.
  - Sets `verified=True`, `no_change=False`, `submitted_at=now()` on all unverified `VendorAudit` records for the cycle, excluding the skip company.
  - Stamps `RentalStaging` rows for each submitted vendor with `cycle_week/cycle_year`.
  - Outputs per-vendor confirmation and final count.
- **README Testing Section:** Documents window rules, both commands with all args, and a step-by-step Week 18 scenario.

#### Vendor Cadence Restoration
- **`VendorCompany.cadence` Field:** New `CharField` with `SubmissionCadence` choices, default `weekly`. Controlled via Django admin.
- **Migration `0016_vendorcompany_cadence`:** Applied. All 25 active vendor companies default to `weekly`.
- **6 Monthly Vendors Set:** Christensen Nixon and Davis, Davidson PLC, Lee-Jordan, Morales Allen and Jones, Preston LLC, West Inc — updated to `monthly` per `Vendor_Cycles.md`.
- **`advance_cycle` Updated:** Fetches `name` + `cadence` from all active `VendorCompany` rows in one query. Stamps each new `VendorAudit` with the correct cadence. Console output labels each created record with its cadence.
- **Historical Backfill:** 69 existing `VendorAudit` records corrected via one-time script.

## Functional Requirements

### Submission Window
- **FR-SW-01:** Vendor action endpoints (`declare_no_change`, `no_change_ajax`, `csv_upload`) must reject submissions if `RentalMaster` rows exist for the current week, regardless of template state.
- **FR-SW-02:** The `vendor_dashboard` view must derive `window_closed` from a live `RentalMaster` queryset check at each page load — not from a stored flag.
- **FR-SW-03:** The submit button must display a locked "Submission Window Closed" indicator (not an active button) whenever `window_closed` is true.
- **FR-SW-04:** The CSV upload panel must not be rendered when `window_closed` is true or when the vendor has already submitted.

### Testing Commands
- **FR-TC-01:** `reset_week` must delete master rows and reset audit records atomically within a single DB transaction.
- **FR-TC-02:** `bulk_submit_vendors` must not modify the designated skip vendor's audit record under any condition.
- **FR-TC-03:** Both commands must accept `--week` and `--year` arguments and default to the current ISO week/year.
- **FR-TC-04:** Both commands must be documented in the README Testing section with example invocations.

### Vendor Cadence
- **FR-VC-01:** `VendorCompany` must store a `cadence` field (`weekly` or `monthly`) that is editable via Django admin.
- **FR-VC-02:** `advance_cycle` must read cadence from `VendorCompany` and write the correct value to each new `VendorAudit` record.
- **FR-VC-03:** Cadence on a `VendorAudit` record must not change retroactively if the company's cadence is updated — it is a snapshot at cycle creation time.
- **FR-VC-04:** All 25 active vendor companies must have their cadence correctly set per `Vendor_Cycles.md` (6 monthly, 19 weekly).
