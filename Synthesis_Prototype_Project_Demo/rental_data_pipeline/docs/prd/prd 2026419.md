## Product Vision
Deliver a fully operational equipment rental data platform with a closed vendor compliance loop, automated deadline enforcement, and an embedded Plotly analytics tab — enabling operations and leadership to make rent-vs-buy decisions from trusted, timely data served directly from the Django portal.

## Objectives
- Close the vendor compliance loop with an explicit "No Changes this week" submission path.
- Automate deadline detection and SMTP notifications to reduce manual follow-up.
- Deliver an embedded `/analytics/` tab with role-scoped Plotly charts reading from `rental_master` and `vendor_audit` — replacing Power BI as the primary reporting layer for this build.
- Introduce rent-vs-buy indicator logic to support prescriptive reporting.
- Defer Power BI integration until DB is migrated to PostgreSQL.

## Personas and Permissions
- Administrator: access-control and configuration management in Django admin.
- Junior Super User: weekly review, publish decisions, and analytics consumption via `/review/` and `/analytics/`.
- Vendor: submit equipment updates or declare no changes for the current cycle; restricted to own company data.

- FR-10b: Charts must include: spend by vendor (bar), compliance status by vendor/cycle (heatmap or table), equipment category utilization (line/bar), and rent-vs-buy flag table.

## User Flows

### Vendor Compliance Flow
1. Vendor logs in and navigates to their company suite.
2. Vendor either updates equipment records and submits, or clicks "No Changes this week."
3. Either action writes a submission timestamp to `vendor_audit` and sets `verified = True`.

### Deadline Nudge Flow
1. `check_deadlines` management command is run (manually or via scheduler).
2. Command queries `vendor_audit` for vendors with `verified = False` past the cutoff.
3. SMTP email is sent to each non-compliant vendor; Super User is CC'd.
4. Command output logs the result (sent, skipped, errors).

### Analytics Tab Flow
1. Authenticated user navigates to `/analytics/`.
2. Django view enforces role boundary (junior super user only).
3. Plotly figures are serialized to JSON and passed to the template.
4. Template renders interactive charts in a tabbed layout: Spend, Compliance, Utilization, Rent-vs-Buy.

### Power BI Flow (Deferred)
- Blocked on PostgreSQL migration. No action this session.

### Junior Super User Review Flow
1. Junior super user logs in and is redirected to `/review/`.
2. Page displays all 25 active vendors with current-week submission status badges.
3. Stat cards show aggregate totals (Total / Submitted / Pending / Late).
4. Consolidated equipment table shows all staging rows in Excel-compatible format.
5. Junior super user downloads CSV for offline use or sharing.
6. Junior super user navigates historical weeks via arrow controls.

### Admin Flow (Unchanged)
- Manage users, roles, and operational settings.
- Monitor audit table for compliance gaps.

## Non-Functional Requirements
- Secure session handling and least-privilege access (existing).
- No credentials or secrets committed to source control.
- Audit trail for all submission, approval, and nudge actions.
- Maintainable schema with predictable migration steps.
- Email templates must be clear and actionable for vendor recipients.

## Success Metrics
- Percentage of vendors submitting (update or no-change) by weekly deadline.
- Reduction in manual Super User follow-up emails per cycle.
- Time from submission cutoff to approved dataset visible in the `/analytics/` tab.
- Number of rent-vs-buy candidates surfaced per reporting period.

## Risks and Mitigations
- Risk: SQLite is not a native Power BI direct-query source.
  Mitigation: Power BI deferred; embedded Plotly tab reads via Django ORM — no DB connector needed.
- Risk: SMTP credentials exposure.
  Mitigation: enforce environment variable pattern; add to `.gitignore` and document in README.
- Risk: Rent-vs-buy rate inputs not finalized.
  Mitigation: define placeholder schema now; populate rates in a follow-up pass.
- Risk: Vendor non-adoption of "No Changes" path.
  Mitigation: make it the default prompt after login if no submission exists for current cycle.
