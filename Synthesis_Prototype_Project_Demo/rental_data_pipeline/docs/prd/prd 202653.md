## Product Vision
A fully operational equipment rental data platform with accurate per-vendor cadence tracking, a deterministic reviewer landing experience, a responsive vendor portal that communicates submission window state, and a reproducible grading/demo setup that produces a clean, fully-populated cycle on every run.

## Objectives
- Ensure `VendorAudit.cadence` is always correct — both for new rows and for all historical rows — regardless of when the fix is applied.
- Guarantee that `demo_setup --reset` always produces a complete cycle (all 25 or 19 expected vendors) by running `advance_cycle` after every reset.
- Give reviewers a "first open week" default on `/review/` so they never land on a finished week without navigating.
- Give vendors a clear, forward-looking message when no submission is currently required, including the exact date and time their next window opens.
- Surface per-week monthly vendor obligation status on the reviewer's pending-vendor banner.
- Allow vendors to dismiss the check-in modal without being blocked from the rest of the portal.
- All objectives from prd 2026430.md remain fully implemented and in effect.

## Personas and Permissions
- **Administrator:** Django admin access; manages `VendorCompany.cadence`, user accounts, and `ApprovedEquipmentCategory`.
- **Junior Super User (Reviewer):** Lands on the nearest open cycle week; sees whether monthly vendors are required this week; publishes the week.
- **Vendor:** Sees a contextual banner when the window is closed or not yet open; can dismiss the check-in modal freely; knows exactly when the next window opens.

## Scope

### In Scope (This Session — 2026-05-03)

#### Cadence Data Integrity
- **`_fix_vendor_cadences` in `demo_setup`:** Extended to bulk-update `VendorAudit.cadence` across all historical rows (not just `VendorCompany`). Two ORM `bulk_update` calls — one sets `cadence="monthly"` for the 6 monthly vendors, one sets `cadence="weekly"` for the 19 weekly vendors.
- **`reset_week` Cadence Correction:** After bulk-resetting audit rows to pending, builds `{name: cadence}` map from `VendorCompany` and corrects each audit row's `cadence` individually.
- **`seed_user_schema` Cadence Seeding:** `_get_or_create_company` now passes cadence in `defaults` and explicitly saves it on pre-existing records, making cadence seeding idempotent.

#### `demo_setup` Post-Reset Cycle Completeness
- **`advance_cycle` Always Runs After `--reset`:** Changed condition from `existing_audits == 0` to `existing_audits == 0 or do_reset`. `advance_cycle` uses `get_or_create` so existing rows are safe; only missing vendor rows are added.
- **`--no-submit` Flag:** Wired into `handle()`. When set, `bulk_submit_vendors` is skipped entirely; all vendors remain Pending. State snapshot and walkthrough still print.

#### Reviewer Dashboard: Auto-Advance to Nearest Open Week
- **Lookahead Logic in `weekly_review`:** When no `?week=` param is present, the view iterates up to 4 weeks forward from today's ISO week. Stops at the first week that is unpublished and has at least one `VendorAudit` row. Sets `current_week` and `current_year` to that week before any further queries.
- **Explicit Navigation Preserved:** `?week=` / `?year=` query params still override the auto-detection. The `←` / `Today` / `→` navigation buttons continue to work as before.

#### Reviewer Dashboard: Monthly Vendor Obligation Banner
- **`monthly_required` Context Variable:** Computed in `weekly_review` view as `any(item["audit"] and item["audit"].cadence == "monthly" for item in audit_list)`.
- **Banner Text Extended:** The existing yellow delinquent-vendor ribbon now appends whether monthly vendors are required (`"Monthly vendors are required this week (first full week of [Month])"`) or not required (`"Monthly vendors are not required this week — they already submitted earlier in [Month]"`).

#### Vendor Portal: "Done for Now" Banner
- **`done_for_now` Boolean:** Computed in `vendor_dashboard` view. True when `(audit is None or (audit.verified and window_closed)) and next_audit is not None`.
- **`next_audit` Query:** `VendorAudit` filtered by `vendor_name=company_name, cycle_date__gt=current_cycle_date`, ordered by `cycle_date`, first result.
- **Banner Template:** Orange ribbon displays next window open date/time as `"[Weekday], [Month] [Day] at 12:00 AM CST (Week [N], [Year])"`. Rendered only when `done_for_now and next_audit`.

#### Vendor Portal: `welcomeModal` Dismissable
- **× Close Button:** Absolutely positioned in modal top-right corner. Calls `welcomeDismiss()`.
- **Backdrop Click:** `onclick="if(event.target===this)welcomeDismiss()"` on the overlay div.
- **`welcomeDismiss()`:** Sets session storage key (same key as `welcomeYes`) and calls shared `_closeWelcomeModal()` helper.
- **`_closeWelcomeModal()` Helper:** Extracted from `welcomeYes`. Used by all three exit paths (Yes, No-confirmed, Dismiss) to ensure consistent fade animation.

## Non-Functional Requirements
- All cadence correction operations must be idempotent — re-running `demo_setup` must not corrupt already-correct data.
- Lookahead for reviewer dashboard must not exceed 4 weeks to prevent excessive DB queries.
- Vendor banner must not introduce new DB queries beyond the single `next_audit` fetch.
- `welcomeModal` dismiss must be indistinguishable from the "Yes" path in terms of modal state — no partial-dismiss artifacts.
