## Product Vision
Deliver a fully operational equipment rental data platform with a closed vendor compliance loop, realistic SMTP-driven email notifications, and a validated end-to-end submission pipeline — demonstrated through a structured W17 scenario exercise that proves every submission path (on-time, late, no-change, validation failure, duplicate, and non-submission) functions correctly under production-like conditions. All analytics are delivered in-house through the embedded `/analytics/` tab; no external BI tooling is used.

## Objectives
- Execute all eight W17 vendor submission scenarios (S-01 through S-08) via the existing portal UI and management commands.
- Establish fake email account infrastructure for all 25 vendor users to enable real SMTP delivery of deadline nudges and submission receipts.
- Wire `check_deadlines` to resolve vendor email from `UserProfile` rather than a static list.
- Add post-submission email receipt hook so vendors receive confirmation immediately after submitting.
- Add a `validate_staging_batch` management command for batch re-validation of staged rows.
- Surface a validation error summary on `/review/` so Junior Super Users can identify and act on rows blocked from publish.
- Confirm the Week Comparison analytics tab correctly reflects W17 additions and removals after publish.
- Establish an admin-managed approved equipment category table (`ApprovedEquipmentCategory`) to replace the hardcoded category list and constrain all database records to approved values.

## Personas and Permissions
- Administrator: access-control and configuration management in Django admin.
- Junior Super User: weekly review, publish decisions, and analytics consumption via `/review/` and `/analytics/`.
- Vendor: submit equipment updates or declare no changes for the current cycle; restricted to own company data.

## Functional Requirements

### W17 Scenario Simulation
- **FR-SIM-01:** `simulate_vendor_week --week N` must create or update all required `RentalStaging`, `VendorAudit`, and `UserProfile` records to represent the full S-01 through S-08 scenario mix for week N.
- **FR-SIM-02:** `--dry-run` flag must log all planned actions without committing any DB changes.
- **FR-SIM-03:** S-05 (validation failure) row must set `is_validated=False` and populate `validation_errors` with a human-readable message identifying each failing field.
- **FR-SIM-04:** S-06 (late submission) must set `is_late=True` on the `VendorAudit` record and be identifiable by `check_deadlines` when run with `--cycle-date` set to the W17 Thursday cutoff.
- **FR-SIM-05:** S-08 (duplicate equipment ID) must be rejected at the view layer with a 400-level response or validation error; the duplicate row must not appear in staging.
- **FR-SIM-06:** After publishing W17 rows, the Week Comparison tab on `/analytics/` must surface S-02 vendors in "Placed On-Rent" and S-03 vendors in "Taken Off Rent".

### Email Infrastructure
- **FR-EMAIL-01:** `generate_vendor_emails` must assign a unique `vendor_{company_slug}@example.com` address to each of the 25 vendor `UserProfile` records. Command is idempotent — re-running does not duplicate or blank existing addresses.
- **FR-EMAIL-02:** `check_deadlines` must resolve the recipient email address from `UserProfile.vendor_email`; no hardcoded addresses.
- **FR-EMAIL-03:** A confirmation receipt email must be dispatched to the vendor's `UserProfile.vendor_email` immediately upon successful "Submit" action on the `/vendor/` dashboard. Email must include vendor name, week number, and row count (or "No Changes" text if `no_change=True`).
- **FR-EMAIL-04:** All SMTP credentials must be sourced from environment variables (`EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_FROM_ADDRESS`). No credentials committed to source.

### Approved Equipment Category Management
- **FR-CAT-01:** `ApprovedEquipmentCategory` table must be editable only by superusers via Django admin. Non-superuser staff must not see the table.
- **FR-CAT-02:** The vendor dashboard `<select>` for equipment category must be populated from `ApprovedEquipmentCategory` ordered by `sort_order` then `name`. Vendors cannot type a free-form category.
- **FR-CAT-03:** The analytics category filter datalist must be populated from `ApprovedEquipmentCategory`. All 60 approved categories must appear regardless of whether any data exists for that category.
- **FR-CAT-04:** All existing `equipment_category` values in `RentalMaster` and `RentalStaging` must be in the approved list. Zero unapproved values permitted after the integrity sweep.
- **FR-CAT-05:** The `classify()` function in `backfill_staging_categories.py` must produce only approved category values. Unmapped descriptions fall back to `"Other"` (which is in the approved list).

### Staging Validation
- **FR-VAL-01:** `validate_staging_batch --week N` must re-validate every `RentalStaging` row for week N, update `is_validated` and `validation_errors`, and print a per-row summary to stdout.
- **FR-VAL-02:** `/review/` must display the count of staging rows where `is_validated=False` for the current week, with a link to the Django admin `rental_staging` list filtered to that week and `is_validated=False`.
- **FR-VAL-03:** `publish_to_master` must continue to skip rows where `is_validated=False`, logging each skipped row's `validation_errors` to the admin action message.

### Compliance Reporting
- **FR-COMP-01:** `/review/` stat cards must reflect the correct mixed badge state across all 25 vendors for W17: Submitted, No Changes, Late, and Pending counts must add up to 25.
- **FR-COMP-02:** `check_deadlines --cycle-date 2026-04-23` must return exactly the S-06 and S-07 vendor(s) as unverified past cutoff.
