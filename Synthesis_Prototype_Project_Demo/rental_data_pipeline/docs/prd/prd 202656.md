## Product Vision
A fully operational equipment rental data platform that is documented, verified, and submission-ready. All grader-facing instructions produce correct and reproducible application state. The codebase, database, and documentation are consistent with one another. No unverifiable external claims appear in the portfolio.

## Objectives
- Correct all bugs in management command output and grader-facing README commands so every documented step produces the state it describes.
- Remove all training certificate references (Pluralsight, DataCamp) from pillar assignments, replacing them with verifiable WTAMU curriculum references or removing them entirely.
- Standardize all grader-facing reset commands to use `--full-reset` for a guaranteed clean slate.
- Correct all document dates to May 2026.
- Verify the full grading flow (Steps 1–3) runs without error and produces the documented state.
- All objectives from prd 2026430.md remain fully implemented and in effect.

## Personas and Permissions
- **Administrator:** Full Django admin access. Cannot access `/analytics/`. Manages `VendorCompany.cadence` and user accounts.
- **Junior Super User (Reviewer):** Weekly review, delinquent vendor resolution, publish gating, analytics. The primary grading persona.
- **Vendor:** Submit equipment updates during the open window only; restricted to own company's rows.
- **Grader (External):** A persona introduced for documentation purposes only. Follows the README Grading Flow without modifying code. All commands and flows must be correct for this persona.

## Functional Requirements

### Correctness
- **FR-C-01:** `demo_setup` walkthrough output must dynamically reflect the `--skip` argument at runtime.
- **FR-C-02:** Running `demo_setup --full-reset --backfill` (no `--skip`) must leave exactly `vendor_smith_llc` as the pending vendor.
- **FR-C-03:** Running `demo_setup --full-reset --backfill --no-submit` must leave all 25 vendors Pending with no staging rows.
- **FR-C-04:** Running `bulk_submit_vendors` after Step 1 must mark exactly 24 vendors Submitted, leaving `vendor_smith_llc` Pending.
- **FR-C-05:** All commands in the README Grading Flow must produce the exact state documented in that section.

### Documentation
- **FR-D-01:** No document in the submission package may reference an unverifiable external training certificate.
- **FR-D-02:** All dates in submission documents must read May 2026.
- **FR-D-03:** The grading weeks table must cover both likely grading weeks (W19 and W20) with accurate vendor counts and backfill behavior.
- **FR-D-04:** The `--reset` vs. `--full-reset` distinction must be clearly documented in the command reference flag table.

### Submission Readiness
- **FR-SR-01:** The repository must be in a state that can be cloned, migrated, and graded without any manual file correction.
- **FR-SR-02:** The database shipped with the repository must have W1–W19 published master ledger history and W19 open with 25 vendors Pending (or the grader runs Step 1 to reset to this state).
- **FR-SR-03:** All test credentials documented in the README must authenticate successfully on both the local and hosted demo instances.
