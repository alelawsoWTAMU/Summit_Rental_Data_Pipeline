## Product Vision
A fully operational equipment rental data platform with high-performance analytics, a closed vendor compliance loop, email-based two-factor authentication for all portal users, a reviewer-driven delinquent vendor resolution workflow, and a reproducibly documented environment. The platform enforces data integrity at every layer and delivers responsive analytics regardless of dataset size.

## Objectives
- Eliminate analytics page load and filter lag by removing server-side HTML row generation and replacing DOM-walking filter logic with data-array filtering.
- Restore and harden the dark mode toggle so it is immune to downstream JavaScript errors on any portal page.
- Document all installed packages and environment configuration in README and `requirements.txt` for reproducibility.
- All objectives from prd 2026423.md remain fully implemented and in effect.

## Personas and Permissions
- **Administrator:** Access-control and configuration management in Django admin.
- **Junior Super User (Reviewer):** Weekly review, delinquent vendor resolution, publish decisions, and analytics consumption via `/review/` and `/analytics/`.
- **Viewer *(concept — not implemented in this capstone)*:** Read-only access to `/analytics/` only. Represents an internal company stakeholder (e.g. department manager, executive) who needs spend visibility but has no role in data intake or approval. In a production deployment, this role would be restricted to authenticated users from the company's own email domain — no outside access permitted.
- **Vendor:** Submit equipment updates or declare no changes for the current cycle; restricted to own company data.

## Scope

### In Scope (This Session - 2026-04-24)

#### Analytics Ledger Performance Overhaul
- **`master_all` Removed from View:** `analytics_dashboard` view no longer constructs or passes a `master_all` queryset to the template. The Django `{% for row in master_all %}` template loop is removed. This eliminates double-transmission of ledger data.
- **`dashboard_values` Query Expanded:** Fields `on_rent_start`, `on_rent_end`, `sn_request_number`, and `approved_by__username` added to the `.values()` call so `dashboard_rows` JSON array is complete for both charts and the raw ledger.
- **`record_count` Derived from List:** Changed from `master_qs.count()` (extra DB query) to `len(dashboard_rows)` (free after list construction).
- **`buildLedgerRows(rows)` Function:** New JS function accepts a filtered subset of `dashboardRows`. String-concatenates `<tr>` markup for all matched rows and assigns to `tbody.innerHTML` in a single operation. Includes HTML escaping via `esc()` helper.
- **Rewritten `applyLedgerFilters()`:** Filters `dashboardRows` JS array against `week-picker` value and thirteen per-column text inputs. Calls `buildLedgerRows()` with matched subset. Updates `#ledger-count` text. No DOM node iteration.
- **Initial Render on Load:** `applyLedgerFilters()` called once during page initialization to populate the ledger before any user interaction.

#### JavaScript Crash & Dark Mode Fix
- **`const TD` Temporal Dead Zone Resolved:** `TD` style string moved inside `buildLedgerRows()` as `var TD`. Eliminates the `ReferenceError` that was aborting the entire analytics script block on page load.
- **Early Dark Mode Script — `analytics.html`:** Standalone `<script>` tag immediately after `<body>` initializes dark mode from `localStorage` and wires click handler via `document.addEventListener` event delegation. Runs independently of all other script blocks.
- **Early Dark Mode Script — `weekly_review.html`:** Same pattern applied. Dark mode toggle on both portal pages is now resilient to any subsequent JS error.

## Functional Requirements

### Analytics Ledger Performance
- **FR-PERF-01:** The `analytics_dashboard` view must not pass a `master_all` queryset or render any ledger `<tr>` rows server-side via Django templates.
- **FR-PERF-02:** The `dashboard_values` queryset must include `on_rent_start`, `on_rent_end`, `sn_request_number`, and `approved_by__username` so `dashboardRows` is self-sufficient for both chart logic and ledger rendering.
- **FR-PERF-03:** `buildLedgerRows(rows)` must HTML-escape all user-derived string values before inserting into `innerHTML`.
- **FR-PERF-04:** `applyLedgerFilters()` must filter the JS data array and replace `tbody.innerHTML` in one operation; it must not iterate DOM nodes or toggle `style.display`.
- **FR-PERF-05:** The ledger must be populated on initial page load without requiring user interaction.

### Dark Mode Resilience
- **FR-DM-01:** Dark mode initialization must run in a dedicated `<script>` tag before all other script content in both `analytics.html` and `weekly_review.html`.
- **FR-DM-02:** The click handler must use event delegation (`document.addEventListener`) so it is not dependent on the button element being present at registration time.
- **FR-DM-03:** A crash in any other script block on the page must not prevent the dark mode toggle from responding to clicks.
- **FR-DM-04:** Preference must be persisted in `localStorage` under key `rdp-theme` and restored on page load.

### Environment Reproducibility
- **FR-ENV-01:** `requirements.txt` at the repository root must list all installed packages with pinned versions.
- **FR-ENV-02:** README must document all packages, their versions, and their purpose in a table.
- **FR-ENV-03:** README must document all required `.env` keys and confirm the file is excluded from version control.
