## Product Vision
Deliver a Django-based rental data platform that validates vendor submissions, routes approvals, and powers analytics-ready reporting.

## Objectives
- Standardize intake and approval workflows for 25 vendors.
- Separate untrusted intake data from approved production data.
- Provide role-specific user experience for admin, approvers, and vendors.
- Supply analytics-ready outputs to Power BI.

## Personas and Permissions
- Administrator: full system and user management.
- Super User: review/approve vendor submissions and promote data.
- Vendor: edit and submit only own company records.

## Scope
### In Scope
- Authentication and role-based access.
- Vendor data submission interface.
- Hard validation rules for key fields.
- Staging to master approval workflow.
- Compliance and audit logging.
- Export/connectivity for Power BI.

### Implemented in Current Build
- Branded external-style login page for vendor/admin access.
- Role provisioning for admin, junior super users (x2), and vendor users (1 per company).
- Vendor-scoped visibility in admin for staging/master/audit views.
- Seed commands for user schema and rental data.
- Admin action to publish validated staging rows into master.

### Out of Scope (Current Session)
- Full production deployment hardening.
- Advanced forecasting models beyond baseline rent-vs-buy flags.

## Functional Requirements
- Vendors can view and edit only their own company suite.
- Vendors must either submit changes or mark no changes this week.
- Validation blocks invalid date/currency values.
- Super users can review, approve, and publish to master.
- System tracks submission and verification timestamps.
- Deadline automation flags late vendors and triggers notification.

## Functional Gaps Remaining
- "No changes this week" submission path is not yet complete.
- Deadline automation and email notification flow is not yet implemented.
- Super user approval currently runs through Django admin, not a custom operations UI.

## User Flows
- Vendor Intake Flow: login -> review records -> update or no change -> submit.
- Approval Flow: super user reviews staging -> approve -> publish to master.
- Admin Flow: manage users, roles, and operational settings.

## Non-Functional Requirements
- Secure session handling and least-privilege access.
- Auditability of all submission and approval actions.
- Maintainable schema and predictable migration strategy.

## Success Metrics
- Percentage of vendors submitting by deadline.
- Reduction in manual correction effort.
- Time from submission cutoff to approved dataset publication.

## Risks and Mitigations
- Risk: inconsistent vendor data quality.
- Mitigation: strict validation and clear error messages.
- Risk: missed deadlines.
- Mitigation: deadline checks and notification workflow.

## Acceptance Criteria
- End-to-end vendor submit and super user approval flow is operational.
- Role restrictions are enforced across all primary screens.
- Approved records appear in master and are consumable by reporting.

## Current Acceptance Snapshot (2026-04-12)
- Partially met: vendor and super-user flows are operational through admin screens.
- Met: role restrictions are enforced for current admin-based screens.
- Partially met: approved records can be published to master; reporting integration is still pending.
