## Key Outcomes

### Bug Fix: `demo_setup` Vendor Flow Header Hardcoded
- **Root Cause:** Line 440 of `demo_setup.py` printed `"  ── VENDOR FLOW (submit as vendor_smith_llc) ──"` as a string literal, ignoring the actual `--skip` value passed at runtime.
- **Fix:** Replaced string literal with f-string: `f"  ── VENDOR FLOW (submit as {skip_username}) ──"`.
- **Impact:** The walkthrough output now correctly identifies whichever vendor is left pending, regardless of which `--skip` argument was used.

### Bug Fix: Quick Start Command Left Wrong Vendor Pending
- **Root Cause:** The Quick Start command used `--skip vendor_brown_group`, which auto-submitted Smith LLC. Smith LLC had no real W19 data and would show as Verified on the vendor portal — the opposite of the intended demo state.
- **Fix:** Removed `--skip` from the Quick Start command, relying on `DEFAULT_SKIP = "vendor_smith_llc"`. Smith LLC is left Pending by default.
- **Verified:** `demo_setup --full-reset --backfill` run; output confirmed 24/25 Submitted, Smith LLC Pending.
