## Key Outcomes

### Analytics Ledger Performance
- **Root Cause Identified:** `analytics_dashboard` view passed both a `master_all` queryset (for Django template `{% for row %}` loop) and `dashboard_rows_json` (for JS chart logic) — the same ~6,587 records transmitted twice. `applyLedgerFilters()` walked all `<tr>` DOM nodes and toggled `style.display` on each keystroke, causing layout thrashing.
- **`master_all` Removed:** Queryset eliminated from the view entirely. `record_count` now derived from `len(dashboard_rows)` rather than a separate `master_qs.count()` query.
- **Missing Fields Added:** `dashboard_values` queryset expanded to include `on_rent_start`, `on_rent_end`, `sn_request_number`, and `approved_by__username` — making the JSON array complete for both charts and the ledger.
- **JS-Rendered Ledger:** Django template loop removed. `<tbody id="ledger-tbody">` populated by `buildLedgerRows(rows)`, which string-concatenates `<tr>` markup and assigns to `innerHTML` in one operation.
- **Data-Array Filter:** `applyLedgerFilters()` now filters the `dashboardRows` JS array and rebuilds `innerHTML` with matched rows only — no DOM walking, no show/hide toggling.

### Dark Mode & Script Crash Fix
- **Root Cause:** `const TD` was declared at module scope (line ~1873) but first used inside `buildLedgerRows()` which was called during `applyTopSlicers()` at init (line ~1829). The `const` temporal dead zone threw a `ReferenceError` that silently aborted the rest of the script, preventing both ledger render and dark mode initialization.
- **Fix:** `TD` moved inside `buildLedgerRows()` as `var TD`, eliminating the TDZ entirely.
- **Dark Mode Hardened:** Dark mode initialization and `#theme-toggle` click handler extracted from the bottom-of-script IIFE into a standalone `<script>` tag immediately after `<body>` in both `analytics.html` and `weekly_review.html`. Uses event delegation on `document` — immune to any downstream script crash.
